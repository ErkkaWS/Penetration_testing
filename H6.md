<h2>Mikä ffuf on?: </h2>
    <li>HTTP Bruteforce hyökkäyksien Monitoimityökalu;</li> 
    <li>Lähettää monia pyyntöjä ja tunnistaa anomalioita(poikkeuksia)</li> 
    <li>Voi kohdentaa mitä tahansa HTTP pyyntöjen osaa</li>
    <li>räätälöitävä ja joustava</li></li>
    <li>´ffuf -h´ -komento on aika pitkä, suositeltavaa käyttää `github.com/ffuf/ffuf/wiki/CLl-fIags`</li>
  
<h2>Ffuf kehitys filosofiasta;</h2>
      <li>Ota käyttöön, älä rajoita</li>
      <li>Jos sen pystyy tekemään sovelluksen ulkopuolella, älä implementoi </li>
      <li>"Avoid Magic- pysy idiootti varmana ja ymmärrettävänä"/ ei hokkuspokkus taikoja toiminnassa</li>

<h2>Basics - wordlists, matching and filtering,keywords,complex requests, rate limiting ominaisuudet</h2>
  <li>Wordlists: Kohteen määritys</li>
  <li>Matching and filtering: Tulosten valitseminen, karsiminen ja filtteröinti </li>
  <li>Keywords: Avainsanat, jota haetaan pyynnöistä</li>
  <li>Complex requests: Monimutkaisten pyyntöjen raakadatan tallentaminen, sen käsittely ja uudelleen kättäminen</li>
  <li>Rate limiting ominaisuudet: Pyyntöjen rajaaminen jotta kohde ei kaadu</li>
  
  
<h2>Intermediate - interactive, payload encoder, observe & capture ominaisuudet</h2>
  <li>Interactive: Ajon aikana suodattimien muokkaaminen, tallentaminen ja uudelleen ajo</li>
  <li>Payload encoder: Payloadin enkoodaus ennen kuin syötetään data ffuffille</li>
  <li>Observe & capture: Tulosten tallentaminen ja välittäminen (mm.proxeille)</li>
  
<h2>Advanced ominaisuudet</h2> 
  <li>preflight ja postflight; ffuffin uusi ominaisuus jonka tarkoituksena on auttaa toimimaan CSRF- tokeneita vastaan</li>
  <li>preflight: raakapyyntö ennen fuzzia uuden tokenin saamiseksi</li>
  <li>postflight: raakapyyntö fuzzin jälkeen uloskirjautumiseen/siivoamiseen</li>
  
<h2>Omia mietteitä</h2>

<h2>c2) The interesting non-200</h2>

Seuraavassa tehtävässä tarkoituksena oli suodattaa tulosteesta kaikki ei palvelinstatuskoodi 200 tulokset eli "KAIKKI OK" tulokset näkyville. Vihjeenä tehtävässä oli avainlipukkeet `-mc all` sekä `fc`. Tarkistin jälleen `ffuf -h` mitä nämä avainlipukkeet tarkoittivat ja selvisi että `-mc all`; viittaa vastaamaan HTTP statuskoodia ja `-fc`; viittaa filtterikoodiin eli mihin palvelinkoodiin suodatus osuu. järkeilin tällöin että pitäisi käyttää komentoa `ffuf -w content.txt -u https://ffuf.io.fi/FUZZ -mc all -fc 200`:

<h2>c3) Recursion</h2>

Seuraavan tehtävän tarkoituksena oli suorittaa hakutulos josta pystyisi näkemään rekursiivia polkuja avainlipukkeilla `-recursion`; joka kutsuu rekursiivisten polkujen hakua ja `recursion-depth x`;joka rajoitaa rekursiivisten polkujen hakujen syvyyttä:

Käytin täten komentoa `ffuf -w content.txt -u https://ffuf.io.fi/FUZZ -recursion -ac -recursion-depth 3`, joka hakee rekursiivisia polkuja ja lopettaa 3 osuman jälkeen. Tarkemmin purettuna `-recursion -ac` ffuffia rekursiivisien polkujen hakua ja autokalibroi mitä tuloksia se tulostaa näkyville vain olennaisimmat tulokset sillä ilman `-ac` lipuketta se tulostaisi virheellisesti kaikki `200/OK` statuskoodilla varustetut osumat, `recursion-depth 3`;lopettaa haun kolmannen rekursiivisen osuman jälkeen.

<h2>c9) The login you cannot replay - CSRF token</h2>

Tässä osiossa demotaan uusia preflight/postflight toimintoja; käytin tehtävänannossa annettua valmista komentoa: 

          `cat > login.raw <<'EOF'
          GET /login HTTP/1.1
          Host: ffuf.io.fi
          Accept: text/html

          EOF

          ffuf -w passwords.txt -u https://ffuf.io.fi/login -X POST \
            -H "Content-Type: application/x-www-form-urlencoded" \
            -d "csrf_token=CSRFTOKEN&username=admin&password=FUZZ" \
            -preflight login.raw \
            -preflight-var 'CSRFTOKEN:name="csrf_token" value="([a-f0-9]+)"' \
            -preflight-mode per-request \
            -mc 302`

Sain kuitenkin huomata että olin tehnyt virheen raportin alussa: Olin kopioinut repon ja asentanut 2.1 version jossa ei ole vielä prefligt/postflight toimintoja. Koitin aluksi tehdä pienen korjaus liikkeen ja asentaa go:n `sudo apt install golang-go`, mutta tästä huolimatta: poistin täten Fuffin kokonaan, koska kaikki päivitys yritykset johtivat siihen että 2.1 versio oli silti käytössä:

`sudo apt remove --purge ffuf -y
sudo rm -f /usr/local/bin/ffuf
sudo rm -f /usr/bin/ffuf
rm -f ~/go/bin/ffuf
rm -rf ~/ffuf
rm -rf ~/ffuf-src
go clean -modcache
hash -r`

Tämän jälkeen asensin Ffuffin uudelleen samalla komennolla `git clone https://github.com/ffuf/ffuf ; cd ffuf ; go get ; go build`

jonka jälkeen komento suoriutui niin kuin sen ohjeissa oletettiiin suoriutuvan ja versio vaikutti olevan oikea sillä pre/postflight ominaisuudet olivat olemassa kun käytin komentoa: `ffuf -h | grep -c preflight` ja se ei tulostanut `0`
